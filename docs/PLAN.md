# План проекта (зафиксирован 2026-11-20)

## Решения

- **Стек:** Python 3.11+ + PySide6, USB через libusb1, сборка — uv, дистрибуция — PyInstaller (позже).
- **Глубина:** включена фаза 2 — запуск read-only payload (hekate) для eMMC/батареи/фьюзов.
- **Сценарий:** для себя / несколько консолей (UX без «магазинных» наворотов).
- **Язык UI:** трёхъязычный RU/EN/ZH (китайский добавлен 2026-11-20), переключатель в GUI, выбор сохраняется.

## Фазы

### Фаза 0 — каркас ✅
Структура папок, git, зависимости, заготовка GUI с вкладками.

### Фаза 1 — MVP (USB + RCM + мастер поломок) ✅ (2026-11-20)
1. **USB-монитор:** cfgmgr32 (CM_Get_Device_ID_ListW) — детект без драйвера;
   APX/RCM `0955:7321`, MTP `057E:2010`; автообновление 2 с. (SetupAPI отказал
   с ERROR_INVALID_PARAMETER на машине разработки — см. enumerate_win.py.)
2. **RCM-диагностика:** чтение 16-байтного Device ID (bulk EP 0x81, по fusee-launcher),
   только чтение, без эксплойта.
3. **Определение ревизии:** по серийнику (черновая таблица префиксов; точная
   проверка patched/unpatched — фаза 2).
4. **Мастер поломок:** 5 групп × 12 симптомов × 25 причин, приоритезация.
5. **Отчёт:** TXT/JSON в reports/, сборка из снапшотов вкладок.

### Фаза 2 — глубокая диагностика 🔶 (2026-11-20)
**Сделано:**
1. Отправка payload через fusée gelée (`usb/payload.py`): сборка образа по
   fusee-launcher (заголовок 680 → указатели 0x4001F000 → intermezzo → payload
   на 0x40020000), запись чанками 0x1000, триггер GET_STATUS 0x7000.
   Срыв USB = успех. Только RAM, подтверждение в GUI.
2. Собственный intermezzo (`tools/build_intermezzo.py`): своя ARM32-реализация
   алгоритма, ручное кодирование + верификация capstone (дизасм сверяется 1:1).
3. Статус драйвера APX (service = WinUSB?) + локализованный Zadig-гайд во вкладке RCM.

**Переосмыслено (важно):** hekate/nyx — интерактивный payload, свои данные
(eMMC health, батарея, фьюзы) показывает НА ЭКРАНЕ КОНСОЛИ и по USB не отдаёт.
PC-side парсинг этих данных требует собственного payload'а (форк hekate с
USB-отчётом) — выделено в фазу 2.5. Текущий сценарий: отправили hekate →
читаем показания на экране консоли.

**Не сделано:** авто-установка WinUSB без Zadig (нужна libwdi-интеграция —
C-библиотека, отдельная задача).

### Профиль консоли А/Б ✅ (2026-11-21)
Введён по живому кейсу (Switch Lite HDH-001 + PicoFly, FCC BKE-HDH001):
- вариант А/Б + тип чипа (PicoFly/HWFly/др) + модель (V1/V2/Lite/OLED);
- ранжирование под профиль: при Б группа «Модчип» первая, модчиповые причины —
  в топ каждого симптома (`knowledge.symptoms.ordered_*`);
- новый симптом-урок кейса: «модчип без SD = чёрный экран» (причина №1 цикла ошибок);
- причина «ремонт стика на Lite = пайка» (несъёмные джойки);
- RCM-статус для Б: предупреждение о принудительном RCM;
- модель ⇒ признак mariko (Lite/V2/OLED); профиль в QSettings и отчёте.

### Фаза 3 — база кодов ошибок

2. История обследований по серийникам.

## Границы read-only
- Ничего не пишем на консоль (eMMC, фьюзы, калибровка — только чтение).
- Payload выполняется в RAM, eMMC не модифицируется.
- Любое действие с риском — с явным предупреждением в UI.
