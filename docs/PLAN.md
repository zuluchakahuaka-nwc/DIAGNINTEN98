# План проекта (зафиксирован 2026-11-20)

## Решения

- **Стек:** Python 3.11+ + PySide6, USB через libusb1, сборка — uv, дистрибуция — PyInstaller (позже).
- **Глубина:** включена фаза 2 — запуск read-only payload (hekate) для eMMC/батареи/фьюзов.
- **Сценарий:** для себя / несколько консолей (UX без «магазинных» наворотов).
- **Язык UI:** трёхъязычный RU/EN/ZH (китайский добавлен 2026-11-20), переключатель в GUI, выбор сохраняется.

## Фазы

### Фаза 0 — каркас ✅
Структура папок, git, зависимости, заготовка GUI с вкладками.

### Фаза 1 — MVP (USB + RCM + мастер поломок) ✅ (2026-11-20)
1. **USB-монитор:** cfgmgr32 (CM_Get_Device_ID_ListW) — детект без драйвера;
   APX/RCM `0955:7321`, MTP `057E:2010`; автообновление 2 с. (SetupAPI отказал
   с ERROR_INVALID_PARAMETER на машине разработки — см. enumerate_win.py.)
2. **RCM-диагностика:** чтение 16-байтного Device ID (bulk EP 0x81, по fusee-launcher),
   только чтение, без эксплойта.
3. **Определение ревизии:** по серийнику (черновая таблица префиксов; точная
   проверка patched/unpatched — фаза 2).
4. **Мастер поломок:** 5 групп × 12 симптомов × 25 причин, приоритезация.
5. **Отчёт:** TXT/JSON в reports/, сборка из снапшотов вкладок.

### Фаза 2 — глубокая диагностика (hekate)
1. Авто-установка WinUSB-драйвера для APX (libwdi / подход TegraRcmGUI).
2. Отправка hekate payload (только RAM, без записи на eMMC).
3. Парсинг вывода: eMMC health, батарея (MAX17050), фьюзы, SoC, RAM.
4. Интерпретация в терминах «что сломалось».

### Фаза 3 — база кодов ошибок
1. Справочник кодов (2162-xxxx, 2110-xxxx, ...) → расшифровка + причины.
2. История обследований по серийникам.

## Границы read-only
- Ничего не пишем на консоль (eMMC, фьюзы, калибровка — только чтение).
- Payload выполняется в RAM, eMMC не модифицируется.
- Любое действие с риском — с явным предупреждением в UI.
