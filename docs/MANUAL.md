# Методичка диагностики Nintendo Switch (DIAGNINTEN98)

Пошаговое руководство для человека: как с помощью программы продиагностировать
консоль, что означает каждый показатель и куда двигаться дальше.
Принцип инструмента: **только чтение**, на консоль ничего не записывается.

---

## 0. Подготовка

```
uv sync
uv run diagninten98
```

Понадобится кабель **USB-C ↔ USB с передачей данных** (не «зарядный»).

### Выставите профиль консоли (вкладка RCM, секция «Профиль консоли»)

**Модель** — по наклейке на нижнем торце консоли (слева от USB-C):

| На наклейке | Модель | Поколение | Особенности |
|---|---|---|---|
| `HAC-001` | Switch V1 | erista (T210) | возможен взлом без чипа (до патча) |
| `HAC-001(-01)` | Switch V2 | mariko (T214) | только с глитч-чипом |
| `HDH-001` (FCC `BKE-HDH001`) | Switch Lite | всегда mariko | **нет вентилятора**, стики несъёмные — замена = пайка |
| `HEG-001` | Switch OLED | всегда mariko | только с глитч-чипом |

**Вариант**: «Б — с глитч-модчипом» ставьте, если на плате есть чип (PicoFly =
мини-платка с RP2040, HWFly и т.п.) — типично для консолей, купленных с рук
взломанными. Признаки: посторонняя мини-плата под задней крышкой, мигающий
светодиод при включении, прошивка «не стоковая».

Профиль сохраняется между запусками и **меняет ранжирование причин** в мастере
поломок: для варианта Б модчип — первый подозреваемый.

---

## 1. USB-тест — главный и безопасный (работает на «мёртвой» консоли)

Подключите консоль кабелем в **любом** её состоянии. Вкладка «USB / Монитор»
обновляется каждые 2 секунды.

| Что показывает монитор | Что это значит | Что дальше |
|---|---|---|
| **Пусто** | SoC не стартует: питание/bootchain | Зарядка при этом работает? → M92T36/BQ24193 живы, смотрим цепи дальше. Группа «Питание» в мастере |
| **APX `0955:7321` висит** | SoC жив, boot ROM работает! | Поломка ПОСЛЕ bootROM: eMMC, прошивка, цепи. Идеальный кандидат для чтения Device ID |
| **APX появляется/исчезает циклически** | При профиле Б: вы видите живой цикл глитча — SoC стартует, чип его роняет | Мастер → группа «Модчип» |
| **MTP `057E:2010`** | Система полностью загружается | Консоль «мёртвой» не является; ищите симптом в дереве |

**Тест кнопкой Power**: при подключенном USB нажмите питание и следите за
монитором — «промелькнул APX» значит: стартует и падает на ранней загрузке.

---

## 2. Вкладка RCM

- **Прочитать Device ID** — 16 байт, чистое чтение. Требует драйвер WinUSB для
  APX (если хинт оранжевый — установите через Zadig: Options → List All
  Devices → APX → WinUSB → Replace Driver).
- **Серийный номер** с наклейки → регион + поколение (таблица черновая,
  точный вердикт patched/unpatched — фаза 2).
- **Payload** — запуск кода в RAM (hekate и т.п.): только для незалоченной
  erista; V2/Lite/OLED (mariko) эксплойт не примут — это норма, не ошибка.

---

## 3. Мастер поломок: как читать

Три колонки: **группа → симптом → причины по приоритету**. Приоритет ≈ порядок
проверки: от статистически частого к редкому. Причины — конкретные проверяемые
узлы (чип, разъём, шлейф), не «что-то сломалось».

Сначала задайте профиль (см. п.0) — от него зависит ранжирование.

### Живые уроки из реальных кейсов

1. **Модчип + чёрный экран → сначала проверьте SD-карту.** Глитч-чипы (PicoFly)
   грузят payload с SD; без карты консоль «не включается» (чип мигает циклом
   ошибки). Это самая частая ложная «поломка» у купленных с рук консолей.
2. **Lite: замена стика = пайка на плате.** Джойки несъёмные. После такого
   ремонта «работает через раз / сама выключается» — сначала контакты и модчип.
3. **«Иногда после разборки работает» = механика.** Контакты разъёмов, зажатые
   провода, трещины пайки — не прошивка и не «материнка умерла».
4. **У Lite нет вентилятора** — «слушаем вентилятор» не применимо: пассивное
   охлаждение, смотрим нагрев корпуса.
5. **Выключение во время игры** = нагрузка: перегрев (паста/пыль, возраст),
   батарея (просадка под нагрузкой), реже — питание.

---

## 4. Отчёт

Вкладка «Отчёт» → «Сформировать» (собирает профиль, USB-состояние, RCM,
выбранный симптом с причинами) → «Сохранить TXT/JSON» в `reports/`.
TXT — читать человеку, JSON — копить историю/сравнивать обследования.

---

## 5. Границы инструмента

- На консоль **не пишется ничего** (eMMC, фьюзы, калибровка — только чтение).
- Payload исполняется в RAM и eMMC не трогает; перед отправкой — подтверждение.
- hekate/nyx показывают свои данные (eMMC health, батарея) **на экране консоли**,
  по USB не отдают — PC-парсинг требует кастомного payload (фаза 2.5).
- Данные по чипам и протоколам — в `docs/FACTS_TO_VERIFY.md` (что проверено,
  что ещё нет).
