# Дерево симптомов → причины

**Источник истины: [`src/diagninten98/knowledge/symptoms.py`](../src/diagninten98/knowledge/symptoms.py).**
Этот файл — указатель, а не данные. Появление/изменение симптомов делается в коде.

## Структура данных

```python
Cause(id, name)          # name = (ru, en, zh) — все три языка обязательны
Symptom(id, name, causes)   # порядок causes = приоритет проверки (частое → редкое)
SymptomGroup(id, name, symptoms)
GROUPS: tuple[SymptomGroup, ...]
```

- Ранжирование: для варианта А порядок причин — как объявлено; для варианта Б
  (модчип) `ordered_causes()` поднимает модчиповые причины (id из
  `MODCHIP_CAUSE_IDS`) в топ, а `ordered_groups()` ставит группу «Модчип» первой.
- Имена микросхем — латиницей во всех языках (M92T36, BQ24193…).

## Как добавить причину/симптом

1. Причину — в словарь `C`: `id` + имя тремя языками.
2. Подключить в симптом через `_c(...)` **в порядке приоритета** (статистика
   ремонтов: от частого к редкому).
3. Если причина модчиповая — добавить id в `MODCHIP_CAUSE_IDS` (тогда при
   профиле Б она сама поднимется в топ во всех симптомах, где встречается).
4. `uv run pytest` — тесты проверят: три языка у всех имён, уникальность id,
   непустые причины, целостность дерева.

## Правила содержания

- Причина = конкретный проверяемый узел (чип/разъём/шлейф/действие), не абстракция.
- Уроки живых кейсов кладём в базу немедленно (пример: `modchip_no_sd` —
  «чип без SD = чёрный экран», причина №1 цикла ошибок PicoFly; кейс
  Switch Lite + PicoFly, 2026-11).
- Сюда же контекст моделей: на Lite стики несъёмные — ремонт = пайка
  (`stick_solder_repair`).
